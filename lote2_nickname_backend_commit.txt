Feature (backend): nickname opcional de usuario

Ticket 19, Feature 5. Columna nueva `nickname TEXT` en users (lazy
migration, mismo patrón que avatar/bio). Se persiste vía PUT
/api/v1/profile igual que bio, con tope de 40 caracteres y string
vacío/whitespace guardado como NULL.

Se expone en dos endpoints, no uno solo:
- GET /api/v1/profile (via _profile_payload) — ya lo esperaba el
  cliente para EditProfileView.
- GET /api/v1/auth/me — necesario para que el Header de Home lo tenga
  disponible sin depender de un fetch extra al perfil extendido.

g.api_user viene de SELECT * FROM users, así que no hace falta tocar
el decorator api_login_required — la columna nueva ya llega sola una
vez migrada.

Sin cambios de comportamiento para nickname NULL: el cliente decide
el fallback a email, el backend solo persiste y devuelve el valor tal
cual.
